## 4. LayoutSpec

| 项 | 设计值 | 落在哪一层 | 实现方式 |
| --- | --- | --- | --- |

页面边距、区块间距、Item 间距、组件内间距分开写，不要共用一个数值。

「行内对齐」按行写：行高 / 行内 padding / 内容对齐（顶或中）/ 文字相对 y——行内 padding 非对称（如 `0 0 12px`）时就是贴顶，不许写成居中。没有卡内行时写「无」。

### 圆角 / 描边（逐元素，不按页写一个值）

| 元素（设计稿 id / name） | 圆角（四角全写） | 描边 / 内边距 | 谁画、谁裁 |
| --- | --- | --- | --- |
| | | | |

设计稿里每个带 `borderRadius` 或可见描边的节点都要在表里有归属行。**节点和分组由脚本数，不要手数**：

```bash
node tools/radius-table.mjs --file <fileId> --layer <layerId>
```

它会把表骨架直接打印出来：遍历全页 `borderRadius`、回查 `splitContainers`（页面级背景，圆角不在 section 节点里）、按「圆角值 + 高」分组、标出圆形 / 胶囊语义，并附上对账行。贴进本节后只补最后一列「谁画、谁裁」；同形状语义的几行可以自己合并，合并后同步改对账行的行数与合并列表。

每张页面必须写下这两个数，并说清差值是哪些同形节点合并进了一行（`N − M` 必须等于合并列表里 Σ(倍数 − 1)，对不上就是有节点既没单独占行、也没被合并计数）：

```text
设计稿 borderRadius 节点数：10 / 本表行数：3（卡片 ×3、按钮 ×6）
```

上面这行成立是因为 (3−1) + (6−1) = 7 = 10 − 3；少写一行而两数不动，差值立刻对不上。嵌套在另一块里的第二个圆角最常这样丢——外面那块写了 4px，里面那块同值 4px 写成纯色，表里只有外层那一行，而两边单看都说得通。圆角写全四角，`8px 8px 8px 0px` 不许写成 `8`；「谁画、谁裁」写清圆角画在哪一层的背景 drawable、有没有铺满的子 View（图片 / 纯色块）需要 `clipToOutline`——只给背景圆角不裁子 View 等于没做（见 [android-pitfalls.md](../android-pitfalls.md)）。本页确实没有圆角元素时表里写「无」、两个数都写 0。

## 6. 实现清单

- [ ] 基类：Activity / Fragment / Dialog / Popup / Adapter / ViewModel 按工程规范继承，入口方法正确
- [ ] 依赖：`UniversalComponents`、`TobBaseResource` 已存在或只补一行
- [ ] 资源名前缀、layout / drawable / mipmap 命名符合模块规范
- [ ] 文案按设计稿直接写在布局里，不抽 `strings.xml`；颜色、尺寸不硬编码
- [ ] 关键数值已按 LayoutSpec 量过实际控件
- [ ] 卡内每一行按设计稿的行内对齐写（行内 padding / 内容顶对齐），不是 `center_vertical` 一把梭
- [ ] 逐元素圆角表的每一行都有真机角点断言（合并行要写明它代表设计稿哪几个节点）
- [ ] 圆角子元素写了裁切机制（背景圆角 + 铺满子 View 时不加裁切等于没圆角），且 `python3 scripts/check-radius-impl.py <模块 res 目录>` 的 ✗ 已清零

## 7. 验收

- [ ] 编译通过
- [ ] 安装的是本次构建的包（`adb install` 输出 `Success`）
- [ ] `adb shell uiautomator dump` 能找到设计稿的每段文案
- [ ] 截图与设计稿逐块比对标题栏、页签、卡片、列表
- [ ] 卡内逐行取 y 与设计稿相对 y 对过（±2dp），同一块至少两行
- [ ] 圆角子元素的角点像素验证过（内缩 ≈ 半径，四个角都看），逐元素圆角表每一行都量过
- [ ] `python3 scripts/check-radius-impl.py <模块 res 目录>` 跑过（静态查「没裁切」与「裁了但不是圆角」两娄，✗ 清零）
- [ ] 未验证的交互和无法完全还原的偏差写进交付说明
