## 4. LayoutSpec

| 项 | 设计值 | 落在哪一层 | 实现方式 |
| --- | --- | --- | --- |
| 页面左右边距 | | | |
| 区块间距 | | | |
| Item 间距 | | | |
| 组件尺寸（宽 × 高） | | | |
| 字号 / 行高 | | | |
| 行内对齐（卡内每一行） | | | |
| 圆角 | | | |
| 圆角实现机制 | | | |
| 对齐关系 | | | |

页面边距、区块间距、Item 间距、组件内间距分开写，不要共用一个数值。

「行内对齐」按行写：行高 / 行内 padding / 内容对齐（顶或中）/ 文字相对 y——行内 padding 非对称（如 `0 0 12px`）时就是贴顶，不许写成居中。「圆角实现机制」写清每个圆角子元素由哪一层画、靠什么裁：容器背景 + 铺满的 `ImageView` 必须写裁切方式，否则圆角不生效（见 [android-pitfalls.md](../android-pitfalls.md)）。本页确实没有卡内行或圆角子元素时写「无」。

## 6. 实现清单

- [ ] 基类：Activity / Fragment / Dialog / Popup / Adapter / ViewModel 按工程规范继承，入口方法正确
- [ ] 依赖：`UniversalComponents`、`TobBaseResource` 已存在或只补一行
- [ ] 资源名前缀、layout / drawable / mipmap 命名符合模块规范
- [ ] 文案按设计稿直接写在布局里，不抽 `strings.xml`；颜色、尺寸不硬编码
- [ ] 关键数值已按 LayoutSpec 量过实际控件
- [ ] 卡内每一行按设计稿的行内对齐写（行内 padding / 内容顶对齐），不是 `center_vertical` 一把梭
- [ ] 圆角子元素写了裁切机制（背景圆角 + 铺满子 View 时不加裁切等于没圆角）

## 7. 验收

- [ ] 编译通过
- [ ] 安装的是本次构建的包（`adb install` 输出 `Success`）
- [ ] `adb shell uiautomator dump` 能找到设计稿的每段文案
- [ ] 截图与设计稿逐块比对标题栏、页签、卡片、列表
- [ ] 卡内逐行取 y 与设计稿相对 y 对过（±2dp），同一块至少两行
- [ ] 圆角子元素的角点像素验证过（内缩 ≈ 半径，四个角都看）
- [ ] 未验证的交互和无法完全还原的偏差写进交付说明
