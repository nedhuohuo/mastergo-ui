## 四、环境坑（实测，建议回灌规范）

1. **`Module.universalComponents` 在本机取不到制品**：常量指向 `UniversalComponents:1.0.7-redesign-9-SNAPSHOT`，Gradle 缓存里只有元数据、没有 aar。表现为 `Unresolved reference: universal`（依赖不在编译类路径上，但不报解析失败）。修法：改用本次构建已包含的本地工程 `implementation project(':UniversalComponents')`（AppShell 的 `supportProject` 本来就用它）。
2. **`UniversalTabLayout` 的父类 `DslTabLayout` 必须由组件库用 `api` 暴露（已根因修复）**：原先 `common/UniversalComponents` 把它写成 `implementation`，导致任何用到 `UniversalTabLayout` 的模块都报「Cannot access class `com.angcyo.tablayout.DslTabLayout` which is a supertype」。已在组件库改成 `api ThirdDependence.TabLayout.tabLayout`（同文件已有 `api ThirdDependence.AndroidX.viewPager2` 的先例）；`ViewPager2Delegate` 只在私有字段用，保持 `implementation`。验证：消费方模块不再声明 DslTabLayout，`:NursingAssessment:assembleDebug` 与 `:UniversalComponents:assembleDebug` 均 BUILD SUCCESSFUL。
   规则：**组件库对外暴露的父类、公开方法/属性签名里出现的第三方类型，必须用 `api`；只内部使用的依赖用 `implementation`，不要让每个消费方重复声明。**
3. **`android.nonTransitiveRClass=true`**：Kotlin 里 `R.color.color_primary` 无法解析（依赖模块的 R 不可见）。颜色要么写在模块自己的 drawable / color 里，要么只在 XML 里用 `@color/...` 引用。当前指示器颜色写在 `nursing_bg_tab_indicator.xml`。
4. **AppShell 是多 flavor 应用**（dev/pre/sit），查依赖要用 `devDebugCompileClasspath`，`debugCompileClasspath` 不存在。

### 真机实测发现的偏差（已修 / 待定）

1. **页签第三项被截断（已修）**：根因有两个——组件的 `NORMAL` 样式默认给 item 内容留 **12dp** 左右内边距（设计稿里 item 宽 = 文本宽，间距才是间隔），且 `WRAP_CONTENT` 模式把**首项前的留白也算一个 itemSpacing**（实测共 4 个），三项总宽超出后第三项被裁 47px。
   修法：`setTabContentHorizontalPaddingPx(0)` + 间距从 40dp 降到 **16dp**。曾试 `EQUAL` 模式，三项全被省略成「压疮评…」，不可用。
   残留偏差：项间距 16dp（设计 39.5dp），右侧留白，后续如要铺满需在组件上补 `space-between` 能力。
2. **设备实际是 361dp 宽 × density 480**，工程装了 AutoSize，dp 按屏宽缩放（实测工具条文本 23.0dp / 设计 24dp、卡片标题 19.3dp / 设计 20dp，约 0.96 倍），因此设计稿的绝对值不能直接当断言，要按缩放后的值量。
3. **提交按钮实测高 40.3dp（设计 46dp）**：待查（ShapeTextView 内部尺寸或 AutoSize 交互），其余尺寸与设计一致。
4. **汇总初始值**：设计稿显示 15/24/20，但按选中项算出来的其实是 I类导管 16 分；当前实现初值是 15/24/20，一进页就被 `refreshSummary()` 重算成 `0/24/16`，`INITIAL_PRESSURE_SCORE` 实际是死代码，需要定：展示设计稿静态值还是实时计算值。
5. **底部阴影（已知偏差，低优先级）**：设计稿是汇总条 `box-shadow: 0px 4px 10px rgba(0,0,0,0.3)`。两种尝试都不对：`elevation="8dp"` 会在汇总条**上方**（列表那侧）投出灰带；改成提交条顶部三档渐变后仍不符合预期。已按你的意思降低优先级，留待后续（方向确认或改 9-patch 实现）。
6. **单选与多选曾分不辨（已临时解决）**：两者都渲染成组件默认的圆形图标。工程内既有图标里**没有方形勾选框**（`component_cb_invoice_*` 也是圆形），设计稿靠形状区分：圆形 = 单选（6 行）、方形 2px 圆角 = 多选（5 行）。
   已用 **shape drawable 自绘**临时顶替（`nursing_ic_checkbox_check/uncheck`）：选中 = 主题色实心块（16x16、圆角 2px，几何取自 section 10 的 `INPUT fill=#3A74FC borderRadius=2px`）；未选 = #999999 1px 描边方框。真机确认两者已能分辨。
   注：曾按设计稿 DSL 把选中态画成「蓝框 + 白色内芯（13×12）」，效果难看，已改为纯色块占位；导出图标到位后直接替换这两个文件。

## 八、与分析的偏差

设计稿把「压疮量表」与「导管量表」画在同一屏内，而页签是三个评估单。当前实现按「页签 = 单表」处理：压疮评估表按设计稿 1:1 呈现两段；导管脱落评估表只呈现导管段；跌倒评估表空态。若设计意图是别的（例如一屏长表单 + 页签只是锚点跳转），需要改数据组织方式。
