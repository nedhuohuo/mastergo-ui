## 8. 读取时发现的坑（交付说明必写）

1. **`_placeholder: true` 在同一份设计里都不自洽**：[4] 的「1分/2分/3分/4分」被标占位，[3] 的同样文本没标；[10] 的「8分」全部被标，[7] 的「2分/3分/4分」没标而「1分」被标。原因只是节点名恰好等于文案。整批按占位符删除会删掉分值。判据只能是语义（是不是真实选项/分值），不是这个字段。
2. **文本颜色有三处来源互相矛盾**，按「同一语义组里出现次数最多的颜色」定，状态差异除外：
   - [2] 页签：`_color`=`#111827`（三项相同），`textColor` 区分 `#3A74FC`/`#666666` —— 这是选中/未选中造成的状态色，不算冲突，按 `textColor` 取；照 `_color` 会丢掉选中态；
   - [7] 营养行 4 个分值：把整组都数一遍是 `#666666` 7 票 vs `#333333` 1 票（仅「1分」节点级`fill`/`_color` 是 #333333），取 `#666666`；
   - [15] 汇总条：整组 `#9E9E9E` 6 票 vs `#333333` 3 票，取 `#9E9E9E`。
   三处冲突都写进交付说明。
3. **`gap` 的语义与 CSS 相反**：DSL `gap:"27px 12px"` 实测列间距 27、行间距 12；照抄成 CSS `gap: 27px 12px` 会变成行 27、列 12，网格直接错位。
4. **底部两条是固定层，与内容重叠 96px**：汇总条 1418–1462、提交条 1462–1550，而最后一行「护理措施」占 1414–1514。内容区必须留出底部高度，让它从固定层下方滚过。
5. **单选选中态在设计稿里不存在**：6 个单选行全部未选中。选中态只能按工程规范推导（描边换主题色或圆点填充），偏差写进交付说明。
6. **设计稿没有禁用 / 错误 / 空态**，不凭空实现。
7. **字体是 MiSans 与 PingFang SC**，Android 无对应字体族，按工程现状用系统字体。
8. **节点名大量过期**：页签项节点名是「联系信息」，汇总条节点名是「压疮等级：轻度危险」而文案是「压疮等级：15分」，评分行标签节点名是「性别」。不能拿节点名当业务语义。
9. **分值不统一，不能一套规则套全表**：I类导管 8分、II类导管 4分（T管 2分）、III类导管 2分、意识 6/4/6分、营养/压疮量表 1–4分，护理措施无分值。分值必须作为数据随选项配置，不能写死在布局里。
