### 中途一次误判（已纠正，别再踩）

真相：应用内容高 2412px（834dp），内容底在 **823.3dp，完整可见**；设计稿内容底 825 < 页面 833 也是一屏放得下，本来就不需要滚。判「压扁 / 裁切 / 被系统栏盖住」只能用截图扫像素，`uiautomator` 只用来确认节点在不在树里、文案和点击目标对不对（这条已在 [android-pitfalls.md](../../android-pitfalls.md)「uiautomator 的 bounds 不是真实绘制范围」里）。`NestedScrollView` 包装已回退，列表仍是 RecyclerView + BRVAH。

## 4. 尺寸 / 颜色：模块不再新建 dp，只留设计稿专有色

按新规范（已写进 skill）：**TobBaseResource 有同值的 dp / sp / 颜色时，模块不许再建一份，别名也不行**。

- **`res/values/nursing_dimens.xml` 已删除**。模块 `values/` 现在只剩 `nursing_colors.xml`。
- 本页 30 个尺寸值全部命中 TobBaseResource 的 `dp_*` / `sp_*` 标尺，布局里直接写 `@dimen/dp_17`、`@dimen/sp_10`、`@dimen/space_micro` 这类引用；原先建的 26 个别名 + 同页旧的 4 个一并删除。
- 同一批改动覆盖了整个模块（`nursing_dimens.xml` 是全模块共用的）：17 个布局 + 19 个 drawable 里共 **208 处** `@dimen/nursing_*` 全部换成 TobBaseResource 引用，另删了 5 个已无引用的旧底栏 dimen。替换后扫 `@dimen/dp_\d+_` 残渣，修掉 10 处前缀撞名（`nursing_report_dot` 命中 `nursing_report_dot_gap` 之类）。
- Kotlin 侧 31 处 `R.dimen` / `R.color` 全部消掉（实测 Kotlin 取不到依赖模块的 R：`com.yilife...tob.resource.R` 编译报 Unresolved）：
  - 页签 / 分段控件的尺寸、字号、间距、配色、背景 → 布局上的 `app:universalTab*` 属性（4 个页面）；
  - 单选 / 多选选项图标尺寸与内边距、自绘方框图标 → item 布局上的 `app:radio_*` / `app:checkbox_*`；
  - chip 间距 → 各 item 布局的 `layout_marginEnd` / `layout_marginBottom`（`OrderActivity`、`OrderHospitalActivity`、`ReportAiAnalysisFragment`、`CustomerFollowAdapter`）；
  - 选中态文字色（下单页性别、医院单模式）→ 新增两个 `res/color/nursing_selector_order_text*.xml` 选择器（`state_selected`，指向 TobBaseResource 颜色），代码只切 `view.isSelected`；
  - 跟进正文块高 → `android:lineSpacingExtra` + 代码切 `maxLines`。
- 颜色方面删掉 12 个条目：10 个指向 TobBaseResource 的别名（order 文字色、follow 标签文字色、follow 分段文字色、弹层宿主底色）+ 2 个与 TobBaseResource 同值却写成十六进制的（`#E4E4ED` → `@color/border_light`、`#E6E6EB` → `@color/fill_darker`）。本页现在只新增**设计稿专有**的颜色：绿/蓝/橙 chip 底与 8% 描边、分隔符 `#DDDFE6`——这些 TobBaseResource 确实没有同值。
- 仍存在的历史别名（**没动，等你决定**）：`nursing_color_report_tag_blue/green/orange`（报告详情的标签三色，TobBaseResource 有同值）。它们在 `ReportAiAnalysisFragment` 里按标签族逐项设色，要去掉得把「分类标签 / 具体标签」各拆成三个色系布局（6 个布局 + 圆点 drawable）——要清就一起清。

## 5. 图标：按你的规则全部用 ic_launcher 占位

按要求「缺失的 icon 图片优先从 TobBaseResource 获取，依旧缺失的使用默认的 ic_launcher 占位图」：

- TobBaseResource 的 AAR（`1.0.1-SNAPSHOT`）里只有 `mipmap/logo` 与 `mipmap/base_ic_no_data` 两个 mipmap，**没有任何图标**（`R.txt` 里 1331 个 dimen、72 个 color、2 个 mipmap）。
- 因此设计稿里的 3 个图标——筛选下拉箭头（22:9353）、展开/收起箭头（22:00178）、评论图标（22:00237）——统一用 ic_launcher 占位图：从 `SchedulingModule` 复制 `ic_launcher.webp` 进本模块 `mipmap-xhdpi/nursing_ic_placeholder.webp`（library 模块引用不到 app 模块的 `@mipmap/ic_launcher`，`resourcePrefix nursing_` 也不允许叫 ic_launcher）。
- 真图标到位后按同名替换即可，布局里 3 处引用都不用动。
- 标题栏返回箭头用的是 `TitleBar` 组件自带的图标，不在占位范围内。
- 头像与卡片 3 的图片是**设计稿的真实素材**（image-resource 原图下载后居中裁方 + 缩放成无损 WebP），没走占位。
- 副作用：预览里能看到 3 个绿色小方块（8dp / 12dp / 14dp 的 launcher 图）。
